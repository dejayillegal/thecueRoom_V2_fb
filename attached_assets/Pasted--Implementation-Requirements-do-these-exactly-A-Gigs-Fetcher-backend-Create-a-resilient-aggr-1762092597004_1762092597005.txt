Create a resilient aggregator architecture:

New package: packages/feeds/ (or reuse existing) with adapters:

Use safeFetch(url, {timeout, attempts}) helper that:

uses AbortController for timeouts

returns structured {ok, status, body, text}; never throws raw HTML

caches HEAD results for images/URLs for a short TTL

For sites that block direct requests, prefer RSS/JSON endpoints or published event pages (parse HTML with a lightweight parser — node-html-parser) — avoid heavy headless browsers on Replit. If headless is required, document it and provide a TEST_MODE fallback.

Normalize every event into this TypeScript type:

type NormalizedEvent = {
  id: string; // deterministic, e.g. source:id or hash
  title: string;
  description?: string;
  startAt?: string; // ISO
  endAt?: string;
  venue?: string;
  city?: string;
  country?: string;
  genres: string[]; // normalized to lowercase
  ticketUrl?: string;
  source: string;
  raw?: any;
};


Filtering rules:

Exclude events matching the Bollywood/pop blacklist: /bollywood|film|movie|celebrity|awards|premiere|cricket/i.

Keep events whose genres or title indicate: techno, house, electronic, minimal, tech-house, drum and bass, bass.

Emits logs with stats: events per source, time taken, errors.

Writes final normalized list to apps/web/storage/events-cache.json (or DB if present).

Backend signup flow:

apps/web/app/api/auth/signup/route.ts:

Validate using Zod (fields, lengths).

If artist flag checked:

Save account with role='artist', verified=false, verification_status='pending'.

Create verification_job row and queue AI verification job (call packages/ai/verify-artist.js) which will:

Basic checks: is social link reachable? does domain match known platforms? (SoundCloud, Bandcamp, Mixcloud, Instagram, Spotify).

Heuristic checks: account age (if possible), number of followers (if public), content matching usernames.

Hash passwords with bcrypt (or argon2) using recommended cost. Store salted hash — never store plaintext.

Send email verification link (dev: log link; prod: SMTP configurable). Use signed tokens (JWT or HMAC) with short expiry.

apps/web/app/api/auth/login/route.ts:

Rate-limit attempts per IP and per account (use node-rate-limiter-flexible or simple sliding-window).

Use HttpOnly, Secure, SameSite=strict cookie for session token (JWT signed with SESSION_SECRET) or server session store. CSRF tokens for stateful POSTs if using cookies.

apps/web/app/api/auth/forgot/route.ts and reset/route.ts:

Tokenized reset links; can be one-time use, expire after 15 minutes.

Throttle reset requests per email/IP.

Role Enforcement:

Middleware apps/web/src/lib/requireRole.ts that protects artist routes (submit-event, ai tools).

E. Artist verification & submit-event

packages/ai/verify-artist.js:

If HF_TOKEN available, attempt model-based verification (free-first).

Otherwise use heuristic scoring:

social profile reachable

profile content includes artist name or recent releases

follower counts (if public)

domain trust (soundcloud, bandcamp → higher trust)

If score >= threshold (configurable), set verified=true. If uncertain, leave pending and push to admin queue.

apps/web/app/api/events/submit/route.ts:

Artist-only. Creates event_submissions.

Immediately runs small validation and enqueues AI verification (packages/ai/verify-event.js).

Return { jobId, status } to client for polling.

Admin UI: /dashboard/admin/events to review pending submissions and approve/deny.

F. Security hardening checklist (mandatory)

All inputs validated with Zod server-side.

Passwords hashed using bcrypt/argon2.

Login rate-limit & IP based blocking after N failures.

Sessions use HttpOnly Secure cookies or signed JWT with short expiry + refresh tokens.

CSRF protection for cookie-auth flows (double submit cookie or CSRF token).

XSS: escape text on server when rendering into HTML and sanitize rich fields (use dompurify server-side if storing HTML).

CSP headers and helmet middleware included.

Ensure safeFetch never returns raw HTML to client JSON parsers (always .text() + safe parse).

Tests for auth flows, brute-force rate limiting, token expiry.

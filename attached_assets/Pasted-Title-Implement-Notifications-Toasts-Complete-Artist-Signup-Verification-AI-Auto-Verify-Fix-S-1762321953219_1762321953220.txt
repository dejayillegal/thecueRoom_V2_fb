Summary
-------
Deliver a robust, high-polish implementation of:
1. Global in-app notifications and toasts (stacked, updatable, accessible).

Implementation roadmap
----------------------
1. **Repo audit & planning**
   - Document current toast & notification systems in docs/IMPLEMENTATION_NOTES.md.
   - Identify shared design tokens (colors, spacing, motion) for reuse.
   - Note where dashboard components live to align modal design.

2. **DB migration**
   - Add the migration file above.
   - Verify table creation and Drizzle schema synchronization.
   - Confirm notification + verification + promo tables exist and foreign keys point to `profiles.id`.

3. **Toasts & Notifications**
   - ToastProvider + useToast hook:
     - Implement `toast({ id?, type, title, message })` and `updateToast(id, { type, message })`.
     - Support states: pending, success, error, info.
     - Animations: slide-in (bottom-right desktop / top mobile), fade-out on timeout.
     - Accessible with aria-live regions.
   - Notifications:
     - GET /api/notifications/list and POST /api/notifications/mark-read.
     - Realtime subscription via Supabase or websocket.
     - NotificationsPanel with filter (All / System / Verification / Promo).

4. **Signup Flow Fixes**
   - Artist signup modal:
     - Ensure Artist checkbox toggles additional fields (Artist Name, Region, Genre, Public Profile, Platform URL, Social links ≤ 5).
     - Client-side validation + inline error states.
     - POST to /api/signup with `is_artist` flag.
   - Server-side signup:
     - Validate payload.
     - Upsert `profiles` record.
     - If artist, create `signup_verifications` row (status=pending).
     - Queue AI verification job (via /api/ai/verify).
     - Return `{ verification:'queued' }`.
   - Client:
     - Show Verification Pending UI (dialog with spinner, Back & Sign Out buttons).
     - Pending toast: “Checking your credentials and artist verification…”
     - On success notification from worker: update toast to success, show “Verification Success” dialog + redirect to dashboard.
     - On rejection: show error dialog and retry guidance.

5. **AI Verification Worker (artist check)**
   - Worker polls signup_verifications (pending).
   - Calls OpenAI (or moderation endpoint) with structured JSON output prompt:
     ```
     {
       "artist_name": "...",
       "profile_url": "...",
       "platform_link": "...",
       "verdict": "approve|reject|manual_review",
       "confidence": 0.0-1.0,
       "reason": "..."
     }
     ```
   - Approves valid profiles (update artist_verified=true, send notification).
   - Rejects or flags suspicious/duplicates (manual review queue).
   - Sends realtime notification and toast update via Supabase.

6. **AI-powered Social Promotion Modal**
   - Modal opens from Artist Dashboard “Create Promo” button or Admin Dashboard “New Promo Post.”
   - Modal structure:
     - Step 1: AI Prompt Input
       - Textarea with helper text: “Describe what you want to promote (release, gig, announcement)…”
       - Optional field: Platform tags (Instagram, SoundCloud, Bandcamp, Mixcloud, etc.)
       - “Generate” button calls POST /api/socialpromo/generate with payload { title, description, tags }.
     - Step 2: AI Generation
       - Modal shows loading spinner and pending toast: “Generating your promo content…”
       - AI returns:
         - `title`: catchy heading
         - `caption`: engaging copy
         - `tags`: 3–5 hashtags
         - `background_prompt`: for image generation
         - `theme_color`: match brand tokens
       - Worker or endpoint calls OpenAI image generation (DALL·E, stable-diffusion, etc.) to create a background image.
     - Step 3: Preview (PromoPreviewCanvas)
       - Show generated content with dashboard styling:
         - Brand gradient, glass overlay, animated elements (subtle pan, opacity fade).
         - Title & caption over background.
         - Buttons: Regenerate / Edit Text / Export.
       - Match dashboard style: same typography, colors, spacing, button variants.
     - Step 4: Export & Download (DownloadDialog)
       - Options: Export as PNG, Export as MP4 (short animation), Export as GIF.
       - Use client-side canvas export for PNG; use headless Puppeteer or server function for MP4/GIF (render + store + return download_url).
       - After export, show success toast and open DownloadDialog:
         “✅ Promo created! Ready to share.”
         Buttons: Download, Copy Link, Share.
       - Store exported promo metadata in `social_promos` table.

7. **AI prompt examples (for backend use)**
   - For text generation:
     > “Generate a high-quality promotional caption for an underground techno artist announcing a new gig or release. Style: concise, authentic, underground tone, no clichés. Include hashtags. Output JSON { title, caption, tags[], tone: 'underground' }.”
   - For image generation:
     > “Generate a background visual for an underground techno event flyer. Neon, dark textures, industrial lighting, moody atmosphere. Return a URL-safe base64 image.”

8. **Download Dialog & Animation**
   - Modal transitions: fade-in overlay, slide-up card motion (match dashboard cards).
   - Buttons use primary accent (lime) and hover glow effect.
   - Optional micro-animations (Framer Motion or CSS keyframes) for share/export buttons.
   - After download completes, show toast “Promo downloaded successfully” with check icon.

9. **ShareMenu**
   - Offer quick links (Copy Link, Twitter/X, Instagram story share via link).
   - Copy link uses clipboard API + toast “Link copied!”.
   - Optional: integrate native Web Share API if browser supports it.

10. **Testing**

    - Storybook:

11. **Accessibility & UX**
    - Modals: trap focus, ESC closes, aria-labelledby, aria-describedby.

    - Color contrast: match WCAG AA; primary accent accessible on dark backgrounds.

----------------------------

- Validate AI-generated outputs before rendering to avoid malicious strings.
- Limit image size (max 1080x1080px) and cache results.
- Rate-limit promo generation requests per user.
- Use async worker for heavy image rendering; do not block API responses.
- Log AI cost usage for monitoring.

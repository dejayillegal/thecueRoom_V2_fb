2) AI verification: free-first design

Use two-layer verification:

Heuristics fallback (default): free, deterministic checks:

Validate event date/time format and future date.

HEAD request to ticket URL or venue website; check HTTP 200.

Check presence on at least one external feed (site search, feed cache).

Domain trust list scoring (example: domains in trusted_sources.json get +score).

Producer consistency checks: artist links, known release links.

Output score (0-100) and decision:

score >= 85 → auto_approve

60 <= score < 85 → needs_manual_review

< 60 → suspect (deny or require more info)

Optional HF inference: if AI_PROVIDER=hf and HF_TOKEN present:

Call Hugging Face model with a short prompt that summarizes checks and asks for a judgement. Respect rate limits and timeouts. Use safeFetch and safeJson parsing.

Merge HF output with heuristics; prefer structured decision from HF only when heuristics not deterministic. Always license HF as optional.

Always store verification reasoning in event metadata for admin audit.

3) Privacy & Public Profile rules

Profiles have two text fields: bio_public (shown on public pages) and bio_private (visible only to user & admin).

All social links: user can mark each link public or private.

Public profile endpoint must strip all private fields and any trace of contact info.

Admin endpoints can see private fields (protected by x-admin: true in dev).

Users must explicitly opt-in to make events/public links visible.

4) Ticket generation & RSVP

Free RSVP flow:

User clicks RSVP on event card; POST to /api/gigs/rsvp with userId & eventId.

Create ticket record { ticketId, userId, eventId, issuedAt } and enqueue renderTicket job.

Worker will generate a polished ticket PNG with:

Event title, host, date/time, venue, seat/free, QR code containing ticket verification URL.

Use brand tokens/colors, retina-ready, downloadable.

Return jobId; front-end polls ticket job status and downloads when ready.

Ticket download must trigger browser download with correct headers and content-type. Provide direct /api/gigs/ticket/download/[jobId] returning Content-Disposition: attachment.

Admin may toggle ticket templates & watermark (show app watermark by default).

9) Implementation notes & constraints

Free-first AI: default to heuristics; HF is optional (controlled by AI_PROVIDER=hf).

Workerization: heavy tasks (verification, ticket rendering) must run in worker process (child_process.fork or worker_threads). Limit concurrency via env var.

Streaming: use streaming APIs for all image writes (sharp streams) to avoid buffering.

Cache & dedupe: maintain small LRU caches and hashed dedupe for feeds and events.

Privacy: all public endpoints must enforce data filtering. Admin routes protected by x-admin: true header until a full auth system exists.

Fallbacks: if sharp unavailable, fallback to SVG composition + @svg2png-js or node-canvas to rasterize.

Security: sanitize all user-provided HTML or strings used in SVG overlays (escape to prevent injection).

Rate limits: apply simple rate-limiter to event submit/verify APIs (per-IP).

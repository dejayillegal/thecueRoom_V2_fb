2 — Backend: job & worker infra (core)

Create a safe worker-based AI and long-job infrastructure.

A. packages/ai/worker.js (Node worker)

Uses worker_threads or child_process.fork() to process a job queue stored in file ./.local/ai-queue.json (simple durable queue).

Supported job types:

hfGenerateImage (if HF_TOKEN present) — call Hugging Face Inference API with safeFetch & timeouts.

fallbackSvgRasterize — generate 1024×1024 SVG via packages/ai/impl/fallback-svg.ts and rasterize using sharp or svg2png fallback; write stream to AI_TEMP_DIR/<jobId>.png.

composeTextWatermark — overlay Artist + Release + watermark using SVG overlay + sharp composite or SVG fallback.

verifyArtist — small deterministic verifier: fetch social profile, parse for presence of tracks/links, follower count heuristics. In TEST_MODE it completes fast.

thumbnailProcess — small thumbnail conversions.

Worker must:

Respect AI_WORKER_CONCURRENCY and limit concurrency.

Stream outputs to disk (no huge buffers).

Write status files AI_TEMP_DIR/<jobId>.status.json for polling.

Expose enqueue(job) via IPC or HTTP (we'll call via filesystem queue for simplicity).

B. Helper: packages/ai/impl/utils.ts

safeFetch(url, opts) with AbortController, attempts, backoff, and safe JSON parsing fallback to return {ok:false, text} when non-JSON response.

C. Fallback SVG generator: packages/ai/impl/fallback-svg.ts

Export generateSVG({prompt, preset, artist, release, seed}) returns SVG string (1024x1024) with layered gradients, grain/noise pattern, geometric shapes, subtle lens-glow, and embedded fonts for later overlaid text.

3 — Backend: API routes (Next.js App Router style)

A. apps/web/app/api/ai/env/route.ts → GET { hasAIKey: boolean } (true if HF_TOKEN present)
B. apps/web/app/api/ai/generate/route.ts (POST)

Zod validate: { prompt, preset, artistName, releaseTitle, resolution? }.

Enqueue job in worker queue: prefer HF if HF_TOKEN and model available; fallback to fallbackSvgRasterize.

Return { jobId, status: 'queued' }.
C. apps/web/app/api/ai/job/[jobId]/route.ts (GET)

Read AI_TEMP_DIR/<jobId>.status.json and return { jobId, status, progress, resultUrl? }.
D. apps/web/app/api/ai/result/[jobId]/route.ts → Serve the PNG with Content-Type: image/png.
E. apps/web/app/api/ai/compose/route.ts (POST)

Accept: { jobId, mode:'auto'|'editor', artistName, releaseTitle, watermark, fontFamily, color, size, position }.

Enqueue composeTextWatermark job and return composeJobId.
F. apps/web/app/api/auth/signup/route.ts (POST)

Zod validate signup fields.

Required fields for all: firstName, lastName, artistName, email, password, regionText, primaryGenreText.

If artist===true:

Required: socialProfileUrl (validate host list).

Create user with role: 'artist' & status: 'verification_pending'.

Enqueue verifyArtist job and attach verificationJobId.

Return { userId, verificationJobId }.

Else create role: 'user', status: 'active'.

Hash passwords with bcrypt/argon2; in TEST_MODE can use bcrypt with low rounds.

G. apps/web/app/api/verification/job/[jobId]/route.ts → GET status for verification job.

H. apps/web/app/api/events/submit/route.ts (POST)

Accept event payload: title, venue, city, date/time, ticketUrl (optional), flyer (image upload / base64), isPaid (bool), rsvpLimit, timezone.

Validate: artists and admin only can submit; if artist signs up and artist===true allow submit with status: 'pending' and enqueue verifyEvent job (validate flyer, check duplicates).

verifyEvent job uses heuristics to accept or flag for admin review; if accepted, status: 'published' and send notification.

I. apps/web/app/api/gigs/india/route.ts (GET)

Consolidate many sources; implement per-source fetch handlers that:

Use safeFetch with UA header and timeouts.

Prefer published RSS or JSON APIs if present.

For blocked sources (BookMyShow, DICE), use fallback scraping via packages/feeds/headless.ts but only if the environment has Playwright configured; otherwise rely on sources with public feeds (Rolling Stone India, Zomato Live, Ticketmaster India if exists, Paytm Insider via their RSS/JSON if accessible).

Cache results for 5–15 minutes and return normalized { id, title, venue, city, start, end, url, source }.

In Replit, if headless unavailable, skip headless and log that some sources are skipped.

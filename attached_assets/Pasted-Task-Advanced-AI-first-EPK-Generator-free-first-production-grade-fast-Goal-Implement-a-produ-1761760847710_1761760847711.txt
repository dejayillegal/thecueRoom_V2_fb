Task — Advanced AI-first EPK Generator (free-first, production-grade, fast)

Goal: Implement a production-ready, lightweight, AI-powered EPK (Electronic Press Kit) generator with 3–4 high-quality templates (project-themed), live template preview, drag-and-drop module composer for tech riders (CDJs, mixer, speakers, turntables), tracklist + SoundCloud embed support, photo gallery, press quotes, easy add/remove modules, server-side export (PDF + ZIP), client-side canvas/text editor, and an AI rewrite/suggestion tool that is free-first (Hugging Face optional) with deterministic fallbacks. Must preserve the thecueRoom dashboard style/layout across internal pages.

High-level constraints:

All internal pages keep the project dashboard style, tokens and layout.

Landing page may differ.

No heavy GPU usage in browser. Offload heavy rasterization / PDF generation to a worker. Limit concurrency via EPK_WORKER_CONCURRENCY.

Always return valid JSON from APIs. Use safeFetch wrappers. No .json() blind calls.

Implement tests (unit + e2e scroll/perf), diagnostics, and CI-friendly acceptance checks.

No TODOs in committed code. If native modules fail (sharp / puppeteer), implement TEST_MODE fallback.

Files to create / update (implement fully — no stubs):

Backend (App Router API endpoints)

apps/web/app/api/epk/templates/route.ts (GET)

Return list of 3–4 templates with metadata (id, name, preview thumbnail path, description, layout schema).

Example templates: brutalist-onepage, gallery-two-column, console-minimal, presskit-compact.

apps/web/app/api/epk/generate/route.ts (POST)

Accept validated Zod body:

{
  templateId: string,
  modules: Module[],   // tracklist, bio, gallery, techRider, links, quotes
  artistName?: string,
  releaseTitle?: string,
  resolution?: number,  // export resolution
  includeWatermark?: boolean,
  exportFormat: 'pdf' | 'zip' | 'png' // pdf or zip assets
}


Enqueue a job (return { jobId, status: 'queued' }). Store job metadata in .local/state/epk_jobs/<jobId>.json.

Offload heavy export (PDF generation, image rasterizing) to worker process packages/epk/worker.js.

apps/web/app/api/epk/job/[jobId]/route.ts (GET)

Return job status: { jobId, status, progress, resultUrl?, error? }.

apps/web/app/api/epk/ai/rewrite/route.ts (POST)

Input: { text, tone?: 'press'|'bio'|'concise'|'brutalist' }.

Implementation:

Primary: If process.env.HF_TOKEN present → call Hugging Face Inference text model (e.g., tiiuae/falcon-7b-instruct or EleutherAI/gpt-neo-2.7B if available) with prompt engineering to rewrite biography in chosen tone.

Fallback: deterministic local rewriter that:

Splits text into sentences, shortens long sentences, swaps passive to active voice heuristics, amplifies scene/venue adjectives, and appends a 1-line call-to-action. Use compromise library or small handcrafted templates.

Always return { ok:true, rewritten: string }. Use safeFetch to guard HF responses and parse text safely.

apps/web/app/api/epk/template-preview/route.ts (POST)

Accept partial data and return rendered HTML preview fragment (server-side render) or valid HTML snippet for client preview. Use server-side rendering to generate consistent printing results (for PDF).

apps/web/app/api/epk/compose/route.ts (POST)

For final composition: server-side stamping of artist + release + watermark onto images if requested. Use sharp streaming and worker.

Worker (heavy tasks — run in background)

packages/epk/worker.js (Node JS)

Implements:

Job queue using p-limit and persistent job files.

Job types: generatePdf, generateZipAssets, composeImage.

Use Puppeteer or sharp + HTML->image pipeline to render the EPK template HTML to PDF (Puppeteer preferred for faithful CSS). If Puppeteer can't install, fallback to html-to-image + sharp server-side composition.

Stream outputs to EPK_TEMP_DIR/<jobId>/ and write meta.json.

Limit concurrency by EPK_WORKER_CONCURRENCY. Use streaming writes to avoid big memory usage.

Emit progress via job metadata file (atomic writes) or EventEmitter (for local usage).

Implement TEST_MODE where smaller/fast operations run and resolve quickly.

Exports & downloads

Server-side PDF export:

Worker uses Puppeteer to open a local template preview HTML (server-side route), render at high resolution, then print to PDF. Ensure CSS print rules included. Use streaming to write PDF file to disk.

ZIP assets:

Worker builds a ZIP with images, rendered PDF, JSON metadata, and small web-preview HTML. Use jszip or archiver server-side streaming.

UX + Performance rules (must be enforced)

Live preview updates must be debounced (300–600ms) for text edits. Use shallow diffs for template preview payloads.

Workerize heavy operations (PDF/ZIP/image composition). Client should only poll job endpoint and show progress bar.

Use streaming and file writes — do not keep large buffers in memory.

Use IntersectionObserver + lazy loading for gallery thumbnails.

Use memoization (React.memo) for repeated small UI components.

Avoid CSS properties that cause heavy repaints on the main thread (no heavy backdrop-filter on internal pages).

Use aria-* for drag & drop and ensure icon+label accessibility.

AI usage: Free-first strategy

Primary: If HF_TOKEN present, call Hugging Face text-generation Inference API for rewrite suggestions. Build prompts to rewrite biography in different tones and lengths.

Secondary (fallback): Use local rewrite heuristics:

Sentence splitting, shorten long sentences, prioritize active verbs, add performance highlights and concise CTA.

Provide prebuilt phrase templates and synonyms to suggest.

Image generation for placeholder hero images in templates: do not depend on paid APIs. Use:

Procedural SVG generator (used elsewhere) to generate stylized hero images on the fly for previews (fast and deterministic), or

Use HuggingFace image models only if token present; otherwise use SVG fallback.

Provide clear UI toggles: "Use HF AI suggestions" only active if token configured.

Implementation notes & helpful prompts for code

Use Zod on every API schema.

Use nanoid for job ids.

Use fs-extra for atomic writes (or fs.promises + rename).

Use sharp streaming .toFile() for composition; if not present use svg→png fallbacks.

For PDF fidelity use Puppeteer page.setContent(previewHtml, { waitUntil: 'networkidle0' }) then page.pdf({ ... }).

Keep template CSS within the epk-templates folder so the server preview endpoint can render the same HTML for PDF.

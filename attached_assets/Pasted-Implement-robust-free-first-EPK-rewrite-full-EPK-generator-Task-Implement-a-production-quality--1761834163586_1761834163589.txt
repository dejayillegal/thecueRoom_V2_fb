Implement robust, free-first EPK rewrite & full EPK generator

Task: Implement a production-quality, free-first AI-powered EPK (Electronic Press Kit) Generator for thecueRoom. Priority: reliable rewrite of biography/description text, full EPK editor (live preview + templates), draggable technical rider elements (CDJs/mixer/speakers icons), PDF export, safe fallbacks (no external key), good performance, no memory leaks.

High-level behavior

Free-first rewrite:

Primary: Hugging Face Inference API (use process.env.HF_TOKEN if provided) calling an instruction-following model (e.g., google/flan-t5-large or declare-lab/flan-alpaca-large if available). Use HF Inference text-generation endpoint with max_length, temperature, and stop safety.

Secondary (if HF_TOKEN missing or rate-limited): attempt an OpenAPI-compatible provider if process.env.PROVIDER_URL + PROVIDER_KEY present.

Tertiary fallback (guaranteed, local): implement a deterministic, high-quality template-based rewrite function (no external API). The fallback should:

Parse user bio into components (genre, experience, notable shows, press quotes, short bio sentences).

Recompose with tone templates (press, concise, promotional, technical) and synonym replacements using built-in small thesaurus wordlists.

Use heuristics to expand bullets into two-line sentences and produce 3-length outputs: short tagline (<= 80 chars), 90–160 char blurb (social), and 300–500 char EPK bio.

Always return structured JSON: { ok:true, source:"hf"|"provider"|"fallback", outputs:{tagline, blurb, epk_bio}, tokensUsed? } or { ok:false, error }.

Server & Worker:

API endpoints (Next.js App Router):

POST /api/epk/rewrite — accepts { text, tone? }, returns re-written outputs (uses HF -> provider -> fallback). Validate with Zod. Always JSON.

POST /api/epk/render — accepts full EPK JSON and template name. Enqueues a render job and returns { jobId, status: "queued" }.

GET /api/epk/job/[jobId] — job status/progress/result (PDF/ZIP URL).

GET /api/epk/template-preview?template=... — returns small HTML fragment for preview rendering (used by front-end to show live preview quickly).

Worker process (packages/ai/worker.js or apps/web/worker/epk-worker.js):

Handles heavy tasks: HTML → PDF via headless Chromium (Puppeteer) or html-pdf fallback; zipping assets; server-side compose of cover art if needed.

Limit concurrency with EPK_WORKER_CONCURRENCY env var (default 1).

Use streaming and temp files in EPK_TEMP_DIR and auto-cleanup older than X hours.

Provide progress events via status file or simple in-memory map (persist to .local/state).

PDF / ZIP output:

Prefer Puppeteer (headless Chromium) if available; fallback to @react-pdf/renderer or html-pdf when Chromium unavailable.

HTML template must be responsive and use the dashboard theme tokens and fonts.

Include embedded links in PDF where applicable.

ZIP contains epk.json, press-images/, cover.png, epk.pdf.

Performance & safety:

Debounce rewrite requests and live-preview updates.

Workerize PDF generation and image composition.

Limit uploaded image size (max 5MB) and auto-resize thumbnails on upload using sharp or canvas fallback.

Safe fetch: never call .json() directly. Use safeFetch that reads text then attempts JSON.parse.

Rate-limit rewrite endpoint per-IP (simple throttler).

Ensure no memory leaks: stream files, sharp pipelines must pipe to file streams, clean up ImageBitmap and close browser instances.

Fallback behavior summary:

If HF_TOKEN exists, use HF. If HF fails or is rate-limited, try PROVIDER_URL if configured. If both absent or fail, use local template fallback. UI should show source so admin can see which method was used.

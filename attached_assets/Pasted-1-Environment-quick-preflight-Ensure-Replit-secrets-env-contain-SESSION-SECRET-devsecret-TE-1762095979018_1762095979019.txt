3) Backend: Signup endpoint & verification job
Files to update/create

apps/web/app/api/auth/signup/route.ts (or existing auth route)

Validate with Zod (firstName, lastName, artistName, email, password, artist?: boolean, socialProfileUrl?).

If artist === true:

Ensure socialProfileUrl is a valid URL and matches allowed host list (soundcloud.com, bandcamp.com, instagram.com, mixcloud.com, spotify.com).

Create user record with role: 'artist' and status: 'verification_pending'.

Enqueue verification job via worker queue: call worker (child process / packages/ai/worker.js) with { type: 'verifyArtist', userId, socialProfileUrl, seed }.

Return { ok:true, userId, verificationJobId }.

If artist === false:

Create user record role: 'user', status: 'active' (or normal flow).

Return { ok:true, userId }.

apps/web/app/api/verification/job/[jobId]/route.ts

GET status: return { jobId, status: queued|running|done|failed, result?: {...} }

Pollable by frontend modal.

Worker: packages/ai/worker.js or packages/ai/worker.ts

Add handler verifyArtist:

If TEST_MODE === 'true' simulate verification with deterministic delay (2s) and verified: true.

Otherwise, attempt:

Fetch socialProfileUrl, parse for signals (followers count if available), run small heuristics (presence of tracks, posts, profile image).

Optionally call HF or open-source LLM only if configured — but default: local heuristics + deterministic scoring.

Save job result to AI_TEMP_DIR/verification-<jobId>.json and write status updates for polling.

Notify admin via logs/verification.log and (if admin socket present) emit event.

Ensure worker uses streaming, no large memory buffers, and respects AI_WORKER_CONCURRENCY env var.

apps/web/app/api/auth/check-availability/route.ts (if missing)

GET params: ?artistName=... or ?email=...

Rate limit (20 req/min per IP)

Check DB for duplicates and return { available: true|false, reason? }.

DB changes

If using Postgres, migration to include fields role (user|artist|admin), status (active|verification_pending|verified|rejected), social_profile_url, verification_job_id, username.

If no migration system in env, store in data/users.json as fallback for Replit.

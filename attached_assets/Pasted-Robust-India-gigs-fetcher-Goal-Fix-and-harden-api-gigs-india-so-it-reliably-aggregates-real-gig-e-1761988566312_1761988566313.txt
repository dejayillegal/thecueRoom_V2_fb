Robust India gigs fetcher

Goal: Fix and harden /api/gigs/india so it reliably aggregates real gig/event data for India from many sources (APIs, RSS, HTML pages, headless JS where needed), maps each event to a ticketing/landing link when available, gracefully handles DNS/network blocks, and exposes admin controls and diagnostics. Must be fast, memory-safe, paginated, and return deterministic normalized JSON.

Do not ask questions — implement the changes, run tests, commit, and provide the verification outputs asked below.

High level plan (what to implement)

Safe fetch layer with retries, backoff, timeout and structured errors.

Source adapters for each target (RSS, REST API, HTML scrape, headless for JS-heavy sites).

Headless fallback using Playwright when page requires JS to render or returns empty HTML.

Caching & persistence: file-based cache + optional DB caching; TTLs and fallback-to-cache behavior.

Concurrency control using p-limit and environment-configurable concurrency.

Ticket link mapping: try to extract ticket/buy links (BookMyShow, Paytm Insider, Resident Advisor, Festicket, Dice) and include them in normalized event data.

Admin UI + API to enable/disable sources and set poller params. Include endpoint to re-fetch per-source on demand.

Diagnostics & logs: per-source status, error reasons, fetch time, and simple health endpoint.

Tests: unit tests for adapters, safefetch, caching fallback; e2e test script that runs the poller in TEST_MODE and asserts outputs.

Acceptance checks that must pass.

Implementation details & best-practice logic (must be followed)

Parallel & bounded: Run source adapters in parallel but bounded by POLL_CONCURRENCY env var (default 4).

Graceful fallback to cache: If an adapter fails due to DNS/timeout or Playwright not available, return cached results (if available) and mark fromCache:true.

Headless only when required: Adapters attempt simple HTTP/RSS first. If result is empty or HTML contains markers like <script id="__NEXT_DATA__">, call headless helper.

Rate limits & politeness: Add User-Agent: thecueRoom/2.0 (contacts@thecueroom.example) header and respect robots.txt — skip scraping when disallowed.

Ticket link extraction: For each adapter, extract known selectors for ticket links (e.g., .buy-ticket a, a[href*="bookmyshow.com"], a[href*="paytm.com"], a[href*="ra.co"], a[href*="dice.fm"]). Normalize to absolute URLs.

Deduplication: Use deterministic id hashing (sha1 of source+sourceId+startAt) and dedupe by id.

Location normalization: Attempt to map venue city using simple regex or optional geocoding (optional, off by default).

Caching TTLs: default 15 minutes for event sources, admin-configurable per-source.

Avoid blocking main thread: Playwright and heavy scraping must run in child processes or worker threads. Use child_process.fork() or worker_threads with limited concurrency.

Sanitize HTML: Remove scripts from scraped snippets before storing raw.

Failure reporting: Include a human-friendly errors[] array in API response with items like { source, code, message, fromCache }.

Caching behavior

Simulate ENOTFOUND for a source (use test/mocking). The endpoint should return cached events for that source and an errors entry indicating network issue and fromCache:true flag on events.

Admin actions

Admin API can disable a source; after disabling, /api/gigs/india should not call that source.

Performance

A single full fetchAllSources run with default concurrency must finish within a reasonable time (e.g., under 15s for many sources in normal conditions). Use p-limit to avoid saturating CPU.

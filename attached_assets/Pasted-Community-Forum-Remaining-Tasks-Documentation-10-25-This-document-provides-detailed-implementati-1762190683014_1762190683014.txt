Task 17: Implement Rate Limiting
Objective: Protect against spam and abuse with smart rate limits

Components to Create/Modify:

apps/web/lib/rateLimit.ts - Rate limiting middleware
apps/web/app/api/forum/*/route.ts - Apply rate limits to endpoints
Rate Limit Rules:

// Thread creation
- Verified users: 10 threads/day
- Non-verified: 3 threads/day
- Auto-ban if >10 rejected threads in 24h
// Reply posting
- All users: 10 replies/hour, 50/day
- Slow down if 3 consecutive auto-rejects
// Mentions
- All users: 20 mentions/day (prevent mention spam)
// Reactions
- All users: 100 reactions/hour (prevent bot abuse)

Implementation Strategy:

Use rate-limiter-flexible package (already installed)
Redis-backed counters (or in-memory for dev)
Return 429 Too Many Requests with retry-after header
Exponential backoff on repeated violations
Error Response:

{
  "error": "Rate limit exceeded",
  "retry_after": 3600,
  "message": "You can create 2 more threads in 6 hours"
}

Database Operations:

Store visibility in forum_threads.visibility
Check user auth + visibility in API endpoints
Filter threads by visibility in list queries
Permission Logic:

function canViewThread(thread, user) {
  if (thread.visibility === 'public') return true;
  if (!user) return false;
  if (thread.visibility === 'members') return true;
  if (thread.visibility === 'private') {
    return thread.author_id === user.id || 
           thread.mentioned_users.includes(user.id);
  }
}

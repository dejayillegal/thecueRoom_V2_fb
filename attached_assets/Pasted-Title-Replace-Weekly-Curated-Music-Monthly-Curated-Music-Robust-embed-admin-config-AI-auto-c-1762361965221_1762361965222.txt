Title: Replace Weekly Curated Music → Monthly Curated Music (Robust embed + admin config + AI auto-curation fallback)

Summary
-------
Completely replace and remove any existing Weekly Curated Music implementation and implement a new Monthly Curated Music system with the following guarantees:
- Modern, robust, production-quality UI (dashboard style, tokens, animations).
- No runtime errors; defensive input validation and clear error states.
- Admin configuration panel to create, validate, preview, schedule, publish, rollback monthly playlists (Spotify / SoundCloud / Mixcloud).
- Player is Embed + External-Open Fallback (stable, low-cost) for all users.
- If admin forgets to publish a monthly playlist by the scheduled date, an AI-driven fallback runs automatically to generate the Monthly Curated Music using previously provided admin playlists and available metadata.
- Full test coverage (unit + Playwright E2E), Storybook stories, migrations, docs and runbook.

Important: Remove/shadow any old Weekly Curated Music code, config, UI references, routes, DB fields or migrations. Replace all names to Monthly Curated Music. Document removal in docs/IMPLEMENTATION_NOTES.md and commit changes in the same PR.

High-level behavior & requirements
----------------------------------
1. **Full removal of old Weekly references**
   - Find any files, env keys, migrations, UI copy, API routes or DB fields referring to Weekly Curated Music and remove or rename them to Monthly. Leave a migration revert note for rollback. Add a short summary of removed references in docs/IMPLEMENTATION_NOTES.md.

2. **Admin configuration panel (MonthlyPlaylistConfigPanel)**
   - Admins/curators can:
     - Paste one or more playlist URLs (Spotify/SoundCloud/Mixcloud) to evaluate for the month.
     - Validate URLs server-side (extract ID, fetch metadata via client credentials).
     - Preview embed(s) using UnifiedEmbedPlayer and a native small track list (metadata from server).
     - Save as Draft or Schedule publish for a date/time.
     - Publish Now (atomic publish: archive previous live playlist and mark this as live).
     - View history and Rollback to previous live playlist (creates a history snapshot).
     - Toggle Auto-Curation fallback policy and set thresholds (AI confidence threshold, run window).
   - Use drag & drop to reorder playlist entries in the monthly bundle.

3. **Monthly playlist lifecyle**
   - Draft → Scheduled/Queued → Live → Archived.
   - Dashboard (MonthlyPlaylistWidget) only surfaces the active live monthly playlist (status='live').
   - Scheduler/worker publishes scheduled playlists at scheduled_for time (trusted server-side cron).
   - If admin forgets to publish by the scheduled date/time and FEATURE_MONTHLY_AI_FALLBACK is true:
     - Worker runs AI fallback:
       - Gathers historical admin playlists and items (previous months).
       - Uses AI (OpenAI) to score and assemble candidate tracks/playlists (prompt instructs: "Create a high-quality monthly curated playlist in the underground [preferred genres] style using these previous admin playlists and high-quality new finds. Return structured JSON with playlist title, description, items[] with platform & track info and confidence score for each item.").
       - Worker creates a new `monthly_playlists` draft with `auto_curated=true` and status='queued' and sends an admin notification for quick approve OR auto-publishes if admin auto-approve setting enabled and average confidence ≥ threshold.
   - Provide admin notification + email (optional) when auto-curation runs and when it publishes.

4. **Embed + External-Open Fallback playback**
   - Use UnifiedEmbedPlayer for all dashboard and profile placements.
   - Iframe embeds for Spotify/SoundCloud/Mixcloud with lazy-loading and stable layout.
   - Prominent "Open in App / Open in Web Player" button (deep-links for mobile).
   - Fallback native metadata & tracklist if iframe blocked.
   - Per-user playback: each user’s embed operates independently; no cross-user coordination needed.

5. **AI fallback specifics**
   - Worker must:
     - Respect rate limits for metadata fetch & OpenAI calls.
     - Use a structured, safe OpenAI prompt that returns JSON only.
     - Produce `confidence` scores per item and overall playlist confidence.
     - Persist results in `monthly_playlist_auto_jobs` and link to `monthly_playlists`.
     - If auto-publish is enabled and confidence >= threshold, publish atomically and notify users.
     - If confidence < threshold or admin review required, create admin review task and notify admins.

6. **Robustness & error handling**
   - Defensive validation in API routes (Zod).
   - ErrorBoundary wraps heavy UI components to catch and show friendly message.
   - Worker retries transient failures with exponential backoff; logs errors and creates admin alerts.
   - Unit / integration tests for every route and worker behavior (mock OpenAI and metadata APIs in CI).
   - Storybook stories for all UI states (draft, scheduled, queued, live, auto-curated suggestion, rollback).

7. **Admin UX & confirmation**
   - Publishing now: show confirmation modal with "Archive previous live playlist" and "Notify followers" checkboxes.
   - Scheduling: preview card shows scheduled time and timezone conversion; allow editing before publish.
   - Auto-curation: allow admin to configure:
     - auto_publish_on_confidence: true/false
     - confidence_threshold: number (0–1)
     - run_window: number (hours after scheduled time to allow auto-run)

8. **Telemetry & notifications**
   - Emit events: monthly_playlist_scheduled, monthly_playlist_published, monthly_playlist_auto_generated, monthly_playlist_rolled_back.
   - Create notifications for admins (in-app) when auto-curation runs, and for users on publish (if NOTIFICATION_ON_PUBLISH enabled).

- Do not expose service secrets in client bundles.
- Rate-limit auto-curation runs and admin-triggered generation to control cost.

Developer notes / common pitfalls
--------------------------------
- Carefully remove weekly tables/fields and migrate data into new monthly tables (if relevant).
- Worker must be idempotent — a job must not publish the same playlist multiple times in race conditions.
- OpenAI prompts MUST be strict JSON-only responses (use function calling or clear JSON schema).
- Cache metadata responses (Spotify) to avoid rate limits.
- Ensure timezone handling when scheduling publishes; store timestamps in UTC.
- Always create history snapshot before making destructive changes (publish/rollback).
- Add clear admin audit trail for compliance.

🧩 Roles & Access Model

1. Admin

Full access and control.

Can view, approve, or reject artist event submissions.

Can moderate the community forum and handle abuse/spam reports.

Can manage sources and check fetcher/poller health.

Dashboard: system metrics, moderation queue, event approvals, analytics.

2. Artist

Invite-only or AI-verified during signup (AI checks at least one provided social profile).

Can access artist-only features:

AI Cover Art

AI Meme Generator

AI EPK Generator

Community Forum

Curated Weekly Music Feed

Submit Events (pending AI/Admin review)

Ticket Generator (for free RSVP events)

Dashboard: “My Events”, analytics, AI tools, EPK, followers, community links.

3. Regular User

Cannot access artist-only or admin features.

Can browse gigs, RSVP, download tickets, and view attended/upcoming events.

Has News Feed access (music updates, gig radar, AI-curated articles).

Dashboard: Upcoming Events, Past Events, News Feed, Saved Gigs.

🎛️ Functional Architecture Overview

✅ Role-Based Sign-Up / Login

Unified signup modal.

On signup: choose role (Artist / Regular User). Admins are created manually.

Artist signup triggers AI verification (based on one social link).

Regular users bypass verification.

✅ Access Control Middleware

Server-side check (requireRole(role)) wraps protected routes.

Artists and Admins can access /submit-event API.

Regular users attempting to access artist features → redirected to /dashboard/user.

✅ Dashboard Separation

/dashboard/admin

/dashboard/artist

/dashboard/user
Each with unique components and sidebars.

✅ Sidebar

Always visible icon-only menu.

Expands on hover/expand button for desktop.

Collapsible and touch-optimized on mobile.

“Submit Event” visible only to Artists and Admins.

“News Feed” visible to all users.

Logic

Unified aggregator polls each source with retries, caching, and concurrency limit.

Normalize events → { title, date, venue, city, ticket_url, genre, source, description }.

Apply filters:

Exclude any event matching regex: /bollywood|film|movie|actor|celebrity|awards|premiere/i.

Keep only electronic, house, techno, bass, and related subgenres.

Cache results per-source with TTL=5min.

Store normalized events in DB table events.

📡 Event Submission & Verification Flow
Artist & Admin only

Artists: can create and submit events → pending AI review.

Admin: can approve, reject, or edit submissions.

AI: auto-approves if confidence ≥ 0.9; otherwise, queues for admin.

Flow

Artist clicks Submit Event from sidebar.

Fills form (title, venue, city, date/time, genre, description, ticket URL).

Backend:

Validates via Zod.

Creates submission in event_submissions.

Runs AI verification (packages/ai/verify-event.js).

If approved → moves to events table (visible on Gigs page).

If pending → admin notified via dashboard.

📰 News Feed

Accessible to all users (artists + regular users).

Fetched weekly from curated techno/house sources (Mixmag, RA, XLR8R, Attack Magazine, etc.).

Feed cached in news table with title, link, image, and source.

Appears as a sidebar widget and dedicated /news page.

news

id, title, description, image_url, link, source, published_at

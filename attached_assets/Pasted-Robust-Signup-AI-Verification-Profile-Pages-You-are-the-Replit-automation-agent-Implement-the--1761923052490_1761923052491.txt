Back-end routes & worker

apps/web/app/api/auth/signup/route.ts (POST)

Validate using Zod:
{ artistName, email, password, confirmPassword, region, genre, socialLinks[] }

Check uniqueness for email and artistName.

Create user row in DB with status verification: "pending_ai".

Generate autoUsername (see generation rules below) and store username.

Hash password securely (bcrypt/scrypt).

Enqueue verification job to packages/verification/queue with jobId.

Return { ok:true, userId, jobId }. Always return JSON.

apps/web/app/api/auth/check-availability/route.ts (POST)

Input { type: 'email'|'artist', value } validate.

Return { available: true|false, reason?: string }.

Rate limit per IP (simple in-memory limiter in Replit).

packages/verification/worker.js (Node worker)

Accept jobs: verifyUser(userId, socialLinks).

Flow:

Fetch user's socialLinks; perform safeFetch + parse.

Heuristics checks (free-first):

Link domain matches known networks (soundcloud, instagram, bandcamp, spotify, mixcloud, beatport).

Presence of artistName or username on page (text search).

Release signals: presence of tracks/releases, followers counts, profile pictures, recent activity.

Cross-check multiple links for consistency.

If HF_TOKEN present and process.env.USE_HF==='true', call Hugging Face image/text model for additional analysis (optional).

If heuristics pass threshold → mark verification: "verified_ai", emit notification to user and admin audit log.

If heuristics near-threshold or ambiguous → set verification: "pending_admin", create admin task in verification_tasks table, notify admin via apps/web/app/api/admin/notifications and send email (if email configured).

If heuristics fail strongly → mark verification: "rejected_ai", send user email + response including reasons and to re-submit.

Worker must respect VERIF_CONCURRENCY env var, stream logs, and write job metadata at AI_TEMP_DIR/verification/<jobId>.json.

Worker must be memory safe: streaming fetch, timeout per fetch (20s), limit retries 2.

apps/web/app/api/verification/job/[jobId]/route.ts (GET)

Return { jobId, status, progress, result, notes }.

Used for polling from client verification modal.

apps/web/app/api/admin/verification/route.ts (GET/POST/PATCH)

GET: list pending verification tasks (admin auth mock via x-admin:true).

PATCH: approve/deny a taskId — updates user verification status, writes audit log, emails user.

apps/web/app/api/notifications/route.ts

Create notifications for admin+user events.

Use in-memory store or DB table.

packages/verification/utils.ts

safeFetch, safeParseHTML, extractSocialSignals, scoreSignals.

3️⃣ Ingestion Model: REQUEST-DRIVEN, IDEMPOTENT

This is the key design shift.

Instead of:

“Check feed_state → maybe ingest → maybe fail”

We do:

“On request → if feeds table empty OR stale → ingest safely”

Rules:

Ingestion happens inside /api/feeds

Ingestion is non-blocking

Ingestion is idempotent

Ingestion NEVER assumes tables other than feeds

🧩 CORRECT INGESTION FLOW (THIS WILL WORK)
Step A — Request comes in
GET /api/feeds

Step B — Check reality (not imaginary state)
SELECT count(*) FROM feeds
SELECT max(published_at) FROM feeds


That’s it.

No feed_state.

Step C — Decide to ingest
if (feedCount === 0) ingestImmediately()
else if (latestFeedOlderThan(60 minutes)) ingestInBackground()


No locks. No state rows. Time is enough.

Step D — Ingest safely

For each source:

Fetch RSS

Parse items

Normalize

Deduplicate by URL

Resolve thumbnail or fallback

INSERT ... ON CONFLICT DO NOTHING

If a source fails → log and continue.

Step E — Return feeds immediately

Even if ingestion is still running:

Return existing feeds

UI renders instantly

No blank page ever

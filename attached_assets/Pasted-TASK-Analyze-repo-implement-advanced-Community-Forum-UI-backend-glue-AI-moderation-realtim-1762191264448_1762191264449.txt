Functional requirements (must be implemented)
1. Forum list (three-column responsive layout)
   - Left column: categories with counts and icons, filter control, new-thread and AI Summarize CTA.
   - Center column: latest threads list showing avatar, username, badges (Verified Artist / Moderator), thread title, category and status pills, replies count, views count, and timestamp. Each row should be keyboard accessible and clickable to open ThreadView.
   - Right column: top contributors, forum rules, upcoming gigs, and short community cards.

2. Thread view
   - Breadcrumb + title + follow/share buttons.
   - OP box (left) showing avatar, verified badge, role (OP), and any pinned/status label.
   - Posts list with replies, each reply showing avatar, username, badge, content, reactions (upvote/like count), and Reply button.
   - Quick reply composer at bottom with same composer features as full composer (mentions, attachments, AI Assist).
   - Right rail with thread meta (category, status, created_at, participants), contributors, and similar threads.

3. Composer (create thread & reply)
   - Title input, category select, tags input, body textarea (support basic markdown and code snippets).
   - Toolbar: @Mention (autocomplete), Link, Media, Snippet, AI Draft, Verify Artist.
   - Mentions: typing "@" shows a prioritized list (verified artists first). Selecting inserts a mention token in the editor and add mention metadata to the payload.
   - Attachments: upload images/audio to Supabase Storage (signed upload), render thumbnails and audio previews, and save attachment metadata.
   - Save Draft: persist to server and local autosave.
   - Publish Thread: validates inputs and calls POST /api/forum/thread/create.

4. Mentions & profile modal
   - Clicking any username or avatar opens ProfileModal showing left pane profile info (avatar, verified badge, location, genre, member since) and right pane activity list (recent threads).
   - Mention metadata saved server-side and resolves to clickable mention links; hovering shows quick profile tooltip.

5. Verified artist behavior
   - Verified artists display a unique badge and can be prioritized in mention autocomplete.
   - Only verified artists can be bulk-tagged in special posts; others cannot tag verified users in ways that trigger push notifications unless permitted.

6. Realtime & optimistic updates
   - Use existing realtime mechanism in codebase (prefer Supabase Realtime if present).
   - New replies, reactions, and view counters update across open sessions.
   - Implement optimistic UI for reactions & replies with rollback on error.

7. Reactions, views & counters
   - Implement reactions upsert endpoint; allow one reaction type per user per target.
   - Implement view recording endpoint with server throttling (one view per user per 10 minutes).
   - Show live counters and animated state changes on reaction.

8. Moderation & AI verification
   - Server-side moderation pipeline:
     - On thread/reply create, run quick checks (profanity, external link patterns).
     - Call AI moderation endpoint via worker (forumWorker) to classify: allow | flag | block and provide reasons.
     - If flagged: set post.status='pending_review' and add an item in moderation_queue.
     - If blocked: reject request and respond with clear error message for user and appeal instructions.
   - Admin moderation UI to review flagged items with Approve / Reject / Edit actions.
   - Automatic link allowlist for commerce links and only allow official music platforms unless user is verified.

9. Drafts, autosave & restore
   - Autosave to localStorage every 10s and server-side draft every 60s.
   - Draft listing in profile and composer should allow resume.

10. Rate limiting & abuse protection
    - Enforce server-side rate limits (thread create, replies, mentions).
    - Show friendly error messages and exponential backoff.

11. Security & RLS
    - Add Supabase RLS policies (or the codebase equivalent) to restrict create/edit/pin/moderation privileges.
    - Sanitize all inputs and rendered HTML (use a sanitizer library).
    - Ensure uploads are stored in private/public buckets as appropriate and URLs are signed.

12. Tests & storybook
    - Unit tests for composer, mention autocomplete, reply flow.
    - E2E Playwright tests for: create thread, reply in two sessions (realtime), moderation flagging + admin approval, mention flow.
    - Storybook stories for ForumList, ThreadView, Composer, AI Assist modal, ProfileModal.

API contracts & payloads (client-server)
- thread create request POST /api/forum/thread/create:
  - body: { title, body, category_id, tags: [], attachments: [{type,url,meta}], mentions: [{user_id, username}], visibility }
  - response: { ok, thread: {...}, verification: 'approved'|'queued'|'rejected', message? }
- reply request POST /api/forum/thread/reply:
  - body: { thread_id, body, attachments, mentions }
- reaction POST /api/forum/reaction:
  - body: { target_type: 'thread'|'post', target_id, reaction: 'like'|'upvote' }
- mention resolve GET /api/forum/mention/resolve?q=:
  - returns prioritized list of users with flags (verified, moderator)

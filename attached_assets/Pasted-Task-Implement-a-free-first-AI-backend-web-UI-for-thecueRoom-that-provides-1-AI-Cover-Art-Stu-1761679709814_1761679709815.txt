Task: Implement a free-first AI backend + web UI for thecueRoom that provides:
  1) AI Cover Art Studio — generate album/EP/track cover art
  2) AI Meme Studio — fast meme image + text overlay generator with templates
  3) AI EPK (Electronic Press Kit) Generator — auto-layout artist EPK PDF from artist data + images

Important constraints (must obey exactly)
- The assistant must write working TypeScript + Next.js (app router) code for the web UI and server APIs, plus a small Node worker and optional Python worker instructions for local model runners.
- No paid secrets checked into the repo. Use `.env.example` only. If HF/hosted tokens are missing, code must run in `TEST_MODE=true` using fixtures and an entirely free fallback (see below).
- Strict TS: `tsconfig` strict mode must remain on. Pin any added npm packages to exact versions.
- Performance & memory safety: heavy model work must run off the main thread (server worker or background process). Use streaming where possible, offload parsing and image manip to worker, limit concurrency, and enforce memory caps.
- Canonical branding: use `/apps/web/public/logo.svg` verbatim and the design tokens in thecueRoom preamble. Do not alter the logo.

High-level architecture to implement (assistant decides code details)
- Frontend pages:
  - `/ai/cover-art` (Cover Art Studio)
  - `/ai/meme-studio` (Meme Studio)
  - `/ai/epk-generator` (EPK Generator)
- Server API endpoints (Next App Router `app/api/.../route.ts`):
  - `POST /api/ai/job` — accepts job request (type: 'cover'|'meme'|'epk'), returns job id (202)
  - `GET /api/ai/job/[id]` — returns job status & result
  - `POST /api/ai/generate/cover` — direct quick-gen endpoint for small free fallback SVG generator (sync, low-memory)
  - `POST /api/ai/generate/meme` — sync fast meme generator (sharp + templates)
  - `POST /api/ai/generate/epk` — generates EPK HTML -> PDF via puppeteer in worker (TEST_MODE uses fixture)
- Background worker & queue:
  - Lightweight in-process queue for dev backed by sqlite jobs table; worker processes jobs with concurrency limit (configurable via env).
  - Provide `scripts/worker-start.sh` to spawn worker locally and `scripts/worker-dev-setup.sh` with instructions for optional local diffusers runner.
- Model strategy (FREE-FIRST, robust fallbacks):
  1. Preferred hosted if token present (ENV: HF_API_TOKEN):
     - Use Hugging Face Inference API (free tier available for many users) for large images — but only if token set. Use a pinned Fetch wrapper and stream bytes.
     - If HF token present, use a vetted SDXL or Artistic model slug from HF (assistant should choose a safe default model slug string but code should be data-driven).
  2. Purely free fallback (MUST be present):
     - **Cover art fallback:** deterministic SVG generator (vector shapes, gradients, text layout, procedural patterns) written in TypeScript producing high-res SVG/PNG via `sharp` server-side. This fallback produces visually pleasing, brandable covers and uses little memory.
     - **Meme fallback:** template + `sharp` for text overlay + automatic auto-sizing.
     - **EPK fallback:** HTML renderer using lightweight templates -> PDF via `puppeteer-core` or `pdfkit`. Use server-side html-to-pdf with a small headless option.
  3. Optional local model runner (advanced dev path, documented):
     - Provide `scripts/setup-local-diffusers.sh` and a `python_worker/` sample that uses `diffusers` + `transformers` with CPU-only fallback (instructions: small model or LoRA recommended to keep low memory). This is optional and **must not** be required for tests/CI — only for developers who opt in.
- Memory & concurrency controls:
  - Worker must limit simultaneous image generation jobs (e.g., concurrency=1 or configurable).
  - Stream outputs to disk tmp files (or to Supabase Storage if configured) instead of keeping large buffers in memory.
  - Job lifecycle: ACCEPT -> PENDING -> RUNNING -> SUCCESS/FAILED; keep job metadata in sqlite or Supabase table.
  - Delete temporary files after successful delivery; garbage collect old jobs periodically.
- Security & validation:
  - Use Zod for all request payload validation.
  - Rate-limit unauthenticated calls (simple in-memory token bucket for dev; document production requirement).
  - For EPK PDF signing, add optional HMAC signature with `EPK_SECRET` env var (document in `.env.example`).
- UX & features (advanced, free-first)
  - Cover Art:
    - Presets (neon, geometric, minimal, collage).
    - Color controls (accent color pickers), typographic controls (title/artist, font choices — embed system fonts or web-safe).
    - Aspect/size presets (square 3000x3000, 1600x1600, 1400x700).
    - Variations: allow user to request N variations; worker will create N variants at reduced resolution to conserve memory then upscale optionally (upscale only if HF token or optional local upscaler available).
    - Metadata embed: generate sidecar JSON with prompt, seed, style, and job id.
  - Meme Studio:
    - Templates with safe default fonts & emoji set.
    - Automatic smart text layout (top/bottom), auto-wrap, font-size scaling, outline for readability.
    - Watermark toggle (project brand).
    - Direct "Share to Forum" action that posts to community forum API (mocked in TEST_MODE).
  - EPK Generator:
    - Form to collect bio, images, links, tracks, press quotes; auto-fill from Bandcamp/Discogs/SoundCloud links if available (scrape with respectful timeouts).
    - Preview as HTML + "Export PDF" button; PDF generated in worker and returned as downloadable file.
    - Include cover image (from Cover Art generator) and contact block.
- Caching & thumbnails:
  - Generated assets must be cached (LRU TTL) and served via stable URLs. Add `packages/edge/src/lib/cache.ts` or use sqlite-backed mapping.
  - Provide `scripts/assemble-assets.ts` pattern for large assets and verify checksum in CI (match project LARP).
- Tests & CI:
  - Unit tests (Vitest) for:
    - Zod schema validation
    - SVG cover fallback generator (validate output contains expected elements)
    - Meme template functions (text wrap)
    - EPK HTML sanity
  - Integration tests:
    - Simulate job creation + worker processing in TEST_MODE and assert result file exists and job transitions.
    - Endpoint tests for `/api/ai/job` and `/api/ai/job/[id]`.
  - Add CI steps in `.github/workflows/ci.yml`: install, typecheck, unit tests, worker integration test (TEST_MODE), and static lint.
  - Tests must not require HF token — only run hosted/model tests conditionally if HF_API_TOKEN is provided (skip otherwise).
- Developer ergonomics:
  - Provide clear README updates: how to run in TEST_MODE, how to enable HF token, how to start worker, how to run optional local model (python) and constraints (memory).
  - Add `Makefile` entries: `make dev-ai`, `make worker`, `make test-ai`.
  - Add `pnpm` scripts: `pnpm --filter apps/web dev:ai`, `pnpm --filter apps/web test:ai`.
- Monitoring & observability:
  - Worker logs should emit simple metrics: job processing time, queue length, failures. Provide `scripts/diag/worker-stats.js`.
  - Implement simple metrics endpoint in worker `/metrics` returning JSON (for local dev).
- Performance & memory guardrails (must be enforced in code):
  - Max output pixels per job (configurable by env), default 3000x3000 for cover; worker refuses larger with friendly error.
  - Max concurrent jobs default 1; configurable via `AI_WORKER_CONCURRENCY`.
  - Use streaming writes to disk; never hold > 1x image buffer per worker process.
  - All external fetches must have timeouts (10s for small metadata, 30s for larger fetches).
- UX: immediate responsiveness
  - Job submission must return quickly (202 + job id). Worker processes in background. UI shows optimistic low-res preview if fallback generator available.
  - Polling or WebSocket updates for job progress (implement both: polling default, WebSocket optional if REDIS/MQ present).
  - Provide progress states and partial previews where available.
- Legal & safety
  - Provide content moderation step (simple profanity filter on input prompts and meme text; block extreme content). Use a small wordlist and Zod refinement.
  - Show a notice about artist rights and advise not to create copyrighted portraits.

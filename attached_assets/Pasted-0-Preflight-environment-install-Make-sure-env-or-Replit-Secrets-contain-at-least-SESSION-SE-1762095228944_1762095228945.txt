Make sure .env or Replit Secrets contain at least:

SESSION_SECRET=devsecret
TEST_MODE=true
NODE_ENV=development
POLL_INTERVAL_SECONDS=300
POLL_CONCURRENCY=2
NODE_FETCH_TIMEOUT_MS=15000


If HF_TOKEN present, add it but it's optional.

Install dependencies (if not already):

pnpm -w install

Expected: pnpm completes with no fatal errors.
If native modules fail (sharp etc), confirm TEST_MODE=true for fallbacks.

3) API sanity checks — signup + verification (automated via curl)

A. Create a normal user (non-artist) — should create account and not spawn verification job.

curl -s -X POST http://localhost:3000/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{
    "firstName":"Test",
    "lastName":"User",
    "artistName":"",
    "email":"testuser+normal@example.test",
    "password":"Str0ng!Passw0rd",
    "artist": false
  }' | jq .


Expected JSON keys: { ok: true, userId: "...", role:"user" } (or similar). No verification job.

B. Create an artist signup (artist checkbox = true)

curl -s -X POST http://localhost:3000/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{
    "firstName":"Illegal",
    "lastName":"Artist",
    "artistName":"Illegal (IN)",
    "email":"artist+test@example.test",
    "password":"Str0ng!Passw0rd",
    "artist": true,
    "socialProfileUrl":"https://soundcloud.com/artist-handle",
    "genre":"techno"
  }' | jq .


Expected JSON: { ok: true, userId: "...", role: "artist", verificationJobId: "<uuid>" }

If the response contains verificationJobId, note it.

C. Poll verification job status:

JOBID=<verificationJobId_from_previous>
curl -s "http://localhost:3000/api/verification/job/${JOBID}" | jq .


Expected states progressed: queued -> running -> done (or pending/approved/rejected) and final object contains score or result or verified: true|false. In TEST_MODE it should settle quickly.

Remediation: If signup returns errors, check apps/web/app/api/auth/signup/route.ts and ensure Zod validation returns precise errors; check logs for worker enqueue errors.

5) Gigs fetch diagnostics

Run the provided diagnostic script scripts/diag/check-gigs-fetch.js:

node scripts/diag/check-gigs-fetch.js


What it does:

Executes packages/feeds/aggregator with TEST_MODE=true.

Prints per-source counts, total events, excluded_bollywood_count, and lists sample events.

Expected output summary (example):

🇮🇳 Fetching India gigs from all sources...
✅ RollingStoneIndia: 44 events
✅ ZomatoLive: 61 events
⚠ BookMyShow: 0 events (403/blocked)
⚠ SwiggyEvents: 0 events (blocked)
Total normalized events: 105
Excluded (bollywood/pop): 0
Cache written: /apps/web/storage/events-cache.json


Acceptance: Total normalized events > 0 and Excluded (bollywood/pop) should be 0 (or only non-electronic events filtered out). If BookMyShow or Swiggy unreachable (403/ENOTFOUND), they should be listed as disabled with clear logs (not crash).

Remediation:

If some sources blocked by downstream hosts (403/ENOTFOUND), the aggregator should be detecting and caching fallback sources (RSS, RollingStone, Zomato). If you require BookMyShow, either:

Use BookMyShow public RSS/feed endpoints (if available) or

Add a disabledSources config and document how to enable via admin once hosting permits.

10) If anything fails — quick remediation checklist

safeFetch parse errors / duplicate function:

Ensure there's only one file exporting safeFetch and that imports reference that path. Run a repo grep:

rg "export async function safeFetch" -n


Remove duplicate declarations or consolidate into src/lib/safe-fetch.ts.

BookMyShow / Swiggy / Zomato 403/ENOTFOUND:

Fall back to RSS endpoints or alternative public sources (RollingStone India, Eventbrite, Bandsintown).

Add the blocked source to disabledSources with a helpful log message and a one-line admin toggle.

Playwright / Electron errors on Replit:

Replit often blocks Chromium/Electron. Use TEST_MODE fallback scripts or run Playwright locally for visual tests.

@radix-ui/react-progress missing:

Install pnpm --filter apps/web add @radix-ui/react-progress or replace with simple in-house progress component.

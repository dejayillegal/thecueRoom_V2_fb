5. UI: Forum list (pixel-match)
   - Implement three-column layout: Left categories panel (with counts & icons), Center content (Latest Threads list), Right rail (Top contributors, rules, upcoming gigs).
   - Thread rows must show: avatar, username, badges (Verified Artist, Moderator), thread title, categories & status pills, replies count, views count, and time.
   - Implement filters & sort controls (All / Trending / Unanswered / Sort: Newest).
   - Use CSS to reproduce exact spacing, subtle inner borders, rounded pill CTAs, and gradient glow (use design tokens where available; otherwise use provided hex values).
   - Ensure responsive breakpoints: on mobile, left categories collapse to dropdown; right rail collapses below content.

6. UI: Thread view (pixel-match)
   - Thread header: breadcrumb, title, follow/share buttons.
   - Display OP post with Verified Artist badge and OP label in an owner-styled box on left column (as screenshot).
   - Render replies with avatar, username, badges, content, and actions (upvote, reply, more).
   - Right rail shows thread meta: category, status, created time, participants, contributors list, similar threads.
   - Implement inline badges (Pinned, Unanswered, Feature).
   - Add quick-reply box beneath thread, with placeholder "Write something to the community..." and Invite-first behavior (if member-only).

7. UI: Composer (Create Thread)
   - Composer must include title input, category select, tag selector, body WYSIWYG-like textarea (supports markdown & code snippets).
   - Composer toolbar: @ Mention, Link, Media, Snippet, AI Draft, Verify Artist.
     - Mention: typed "@", autocompletes verified artists and members; selecting inserts mention token with clickable link and stores mention metadata in payload.
     - Media: attach image/audio files (upload to Supabase Storage) and render attachments inline (images thumbnails, soundcloud embeds).
     - Snippet: code block insert.
     - AI Draft: opens AI Assist modal (see below) and can insert AI-suggested title/body/tags.
     - Verify Artist: button that triggers server-side AI identity verification for the provided links (non-blocking; recommended to queue in moderation queue).
   - Composer must support Save Draft and Publish Thread. Save Draft stores to thread_drafts table.

8. UI: AI Assist modal
   - Implement apps/web/src/components/Forum/AI/ThreadAssistModal.tsx UI that matches screenshot: prompt box, suggestions list, Apply to Title/Body/Tags buttons, tone selectors, safety toggles (Check artist/link authenticity, Flag potential spam).
   - AI suggestions should be fetched via POST /api/forum/ai/suggest which calls OpenAI and returns structured suggestions and safety verdicts.
   - Allow user to "Apply Suggestions" or "Insert to Composer".
   - Safety: AI must be run with a prompt that includes 'scam-safe' and returns safety metrics; if unsafe, show clear warning and block applying.

9. Mentions & @-autocomplete
   - Implement client-side mention index that queries /api/forum/mention/resolve?q= to fetch matching usernames (prioritize verified artists).
   - On selecting a mention, store mention: { user_id, username } and convert into persisted mention metadata in forum_posts. When rendering, mention should be clickable and show a hover tooltip with the small profile card.

10. Profile modal
    - Clicking any user avatar or username opens ProfileModal (apps/web/src/components/Profile/ProfileModal.tsx) showing left pane with avatar / basic meta (verified badge, location, genre, following/follow button), right pane with recent activity and mini-thread composer to message.
    - From profile modal, verify that the "View Profile" link opens profile page.

11. Verified-artist mention & tagging rules
    - Only allow tagging/mentioning of verified artists (flag is_artist && artist_verified) in certain public broadcast actions (e.g., highlighting a featured mention).
    - Autocomplete must denote verified artists with a shield icon and sort them to top.

12. Attachments & embedded music
    - Support attachments: images (jpg/png/webp), audio (mp3), and embed links from SoundCloud, Spotify, Bandcamp, YouTube, Mixcloud.
    - On upload, client uploads to Supabase storage via signed upload and saves attachment metadata to thread_attachments.
    - Embeds should show playable widgets when possible (using iframe/embed code) and not block rendering.

13. Realtime updates
    - Use Supabase Realtime subscriptions on forum_threads, forum_posts, reactions, views, and thread_drafts:
      - New replies show in real-time for open threads.
      - Reactions and views update counters in real-time.
    - Implement optimistic UI updates for reactions and replies with rollback on server error.

14. Reactions, Upvotes & Views
    - Add reactions table and API to upsert reaction per user per target.
    - Display upvote counts and implement +/− animation on click.
    - Add view recording endpoint that throttles for repeated views (only one view per user per 10 minutes).

15. Moderation & AI auto-moderation
    - Server-side moderation flow:
      - Use OpenAI moderation endpoint and a custom prompt to analyze thread/post text + attachments. Return verdict: allow | flag | block with reasons (spam, self-promo, hate, doxxing).
      - If verdict=allow ➜ publish normally. If verdict=flag ➜ place into moderation_queue and set post.status='pending_review', notify moderators. If verdict=block ➜ reject publish and show reason to user with appeal instructions.
    - Add admin review UI at apps/web/src/components/Forum/ModerationPanel.tsx:
      - Show moderation_queue with preview, reason, original content, and quick actions: Approve, Reject, Edit+Approve, Ban User, Add to blacklist.
    - Implement automatic link allowlist: allow only official music platforms in posts unless user is verified; if other commerce links detected, flag.

16. Rate limiting & abuse protections
    - Implement server-side rate limits: thread create limit (3 per day non-verified), replies limit (10 per hour), mention limit (20 mentions per day).
    - Implement exponential backoff for users hitting quotas and show friendly message.

17. Thread settings & visibility
    - Support thread visibility: public, members-only, private (invited).
    - Thread settings in composer right rail: visibility, notify (followers of category), status toggles (open/unanswered/allow replies).
    - Persist thread settings in DB and enforce via RLS policies on Supabase to prevent clients bypassing.

18. Drafts & autosave
    - Composer autosaves local draft to localStorage every 10s and pushes server-side draft every 60s.
    - Drafts listed in user profile under "Drafts" and accessible from composer.

19. Performance & memory
    - Use pagination and cursor-based loading for threads and replies.
    - Avoid loading full attachments until needed (lazy load).
    - Ensure no memory leaks in Realtime subscriptions: unsubscribe on unmount.

20. Security (RLS & policies)
    - Add Supabase RLS policies:
      - Only authenticated users can create threads/replies.
      - Only verified moderators or admins can modify moderation decisions or pin threads.
      - Users can edit/delete their own posts within 15 minutes; moderators can edit any.
    - Sanitize HTML rendering server-side (sanitize input to prevent XSS). Render markdown safely using a library like marked with sanitization.

Step 3 — Sign Up tab requirements (left panel)

Implement inside AuthModal -> Sign Up tab:

Fields (all required):

First name (text)

Last name (text)

Artist / Project name (text) -> availability check + creative username generation

Email (email) -> availability check

Password (password) -> strength meter, minimum 10 chars, must include letter + number + symbol

Confirm password (password) -> equality check

Region (text input — single-line, not select)

Primary genre (text input — single-line, not select)

Public profile URL (optional)

Social links input area (list of URLs)

Checkbox: “I agree to Terms & Privacy” (required)

Behavior:

Debounced real-time availability checks for Artist / Project name and Email (400ms debounce). Use the existing availability API: /api/auth/check-availability.

Show green tick when available, red cross when taken or invalid. Provide accessible status text (aria-live="polite").

Auto-generated username: show a small computed username under Artist name (eg underground-illegal-078) and allow user to override it. Display availability tick for username too.

Password strength meter: prefer local component (avoid extra dependencies). Must be keyboard accessible.

On form submit: POST to apps/web/app/api/auth/signup/route.ts (ensure route exists), return { ok, verificationJobId }.

If success: open VerificationModal and begin verification polling.

If failure: show structured errors.

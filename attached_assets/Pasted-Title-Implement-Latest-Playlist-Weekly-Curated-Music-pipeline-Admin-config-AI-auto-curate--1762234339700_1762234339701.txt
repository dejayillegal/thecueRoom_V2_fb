Title: Implement "Latest Playlist" + Weekly Curated Music pipeline (Admin config + AI auto-curate + embeds)

Summary
-------
Add a robust, production-grade "Latest Playlist" feature to the Dashboard for Admins, Artists and Users. Implement an automated weekly curation pipeline that uses AI to discover and assemble high-quality underground music (new finds, high-signal tracks). Admins can review and override the AI-curated playlist before it goes live. The dashboard should embed playlists (Spotify link provided), display metadata, and support manual admin edits and scheduling. Weekly curated playlists must be embeddable and playable in-app.

Spotify sample playlist (for manual test / embed):
https://open.spotify.com/playlist/33TpZTRBetxMqTWC7UQEHy

High-level design & behavior
----------------------------
1. Dashboard widgets
   - Admin: full PlaylistEditor UI (preview tracks, edit metadata, reorder tracks, approve AI-curated playlists, publish/unpublish, schedule publish date/time).
   - Artist: show "Latest Playlist" panel with preview and play controls (Spotify embed) and CTA to "Submit track" (links to event to recommend tracks).
   - User: show "Latest Playlist" panel with embed and "Follow playlist" CTA.

2. Weekly curation pipeline (automated)
   - Worker (packages/server/playlistWorker.ts) runs on a schedule (cron weekly).
   - Steps:
     1. Discovery: query configured sources (Spotify APIs, SoundCloud, Bandcamp RSS, Beatport, Mixcloud, curated feeds) using a mix of heuristics: newly-released tracks in underground tags, trending in niche playlists, artist-follow graph, and curated label releases.
     2. AI filtering & scoring: for each candidate track, call OpenAI (or provided LLM) with a prompt that scores tracks on: underground-ness, production quality, novelty, relevance to genre(s) (techno/house), and probable authenticity. Return a score + short rationale.
     3. Deduplication & metadata enrichment: fetch metadata from platform APIs (e.g., Spotify track metadata and preview_url) and normalize into playlist_items entries.
     4. Assemble top N (e.g., 30) tracks into a candidate playlist and store as a Draft playlist with status='queued' and auto_curated=true.
     5. Create an Admin notification and email (optional) that a candidate playlist is queued for review, with quick-approve option.

   - Admin review path:
     - Admin opens PlaylistEditor, reviews candidate playlist, can remove/add/reorder tracks, edit title/description, then Approve -> publish (status='live' + curated_at timestamp).
     - Option: Admin can also reject (archive) or schedule publish for a future date/time.

3. Auto-approve fallback (optional)
   - If Admin does not act within configurable window (e.g., 48 hours), system can auto-publish if average AI confidence score > threshold. This is a configurable policy toggled by env or admin setting.

4. Embed & playback
   - Use platform embed widgets for playback:
     - Spotify: use Spotify iframe embed or Spotify Web Playback SDK. For simple embed, use iframe with src `https://open.spotify.com/embed/playlist/{playlist_id}` and set width/height/responsive container.
     - SoundCloud/Bandcamp/Mixcloud: use their embed iframes.
   - Provide a shared `EmbedPlayer` component that:
     - Accepts embed_url or platform + id.
     - Renders responsive iframe with lazy-loading.
     - Falls back to a track list UI with links if embeds cannot be loaded (privacy or adblock).

5. Data model & API contract (client-server)
   - GET /api/playlists/list?scope=latest|featured|admin&page=1
     - returns list of playlist summaries (id, title, platform, curated_at, short_description, embed_url, status)
   - GET /api/playlists/get/[id]
     - returns playlist with items array (positioned)
   - POST /api/playlists/admin/update
     - admin-only: { id?, title, description, items: [{track_platform, track_id, track_title, artist_name, track_url, metadata}] }
   - POST /api/playlists/admin/approve
     - admin-only: { id, publish: boolean, schedule_at?: timestamp }
   - POST /api/playlists/curate/run
     - Trigger a manual run of the curation pipeline (admin-only)
   - Worker will push the queued draft to playlists table with auto_curated=true and status='queued'

6. Admin UX expectations
   - PlaylistEditor UI must show:
     - Playlist preview (title, description, small cover if available)
     - Reorderable track list (drag & drop)
     - Inline edit for track metadata and remove/restore
     - "Approve & Publish" button and "Schedule Publish" control
     - Confidence heatmap derived from AI scoring per track (small bar or percentage)
     - Quick-Approve (single click) if curator trusts AI
     - Preview embed (iframe) on right rail

7. Artist and User dashboard behavior
   - Show the currently live "Latest Playlist" (status='live') at top of dashboard panels for Artist and User.
   - Include "Follow playlist" (follow/save) button for users linking to Spotify, and "Suggest a track" CTA for artists that opens a submit modal to propose a track (saved as suggestions table).
   - Past playlists accessible via "Playlist Archive" with pagination.

Security & permissions
----------------------
- Admin-only endpoints must be protected (server-side guard that verifies role from profiles table or Supabase claims).
- Playlist edit/approve actions require admin role or special curator role.
- The worker must store any credential tokens securely (env) and refresh Spotify tokens as needed (client_credentials or refresh flow).
- Sanitize any free-text fields (title/description) to avoid XSS.

How to embed the Spotify playlist in the Dashboard (developer instructions)
-------------------------------------------------------------------------
Use the Spotify embed iframe method for minimal dependency and high reliability:

1. Extract the playlist id from the Spotify URL:
   - Given URL: `https://open.spotify.com/playlist/33TpZTRBetxMqTWC7UQEHy`
   - Playlist id: `33TpZTRBetxMqTWC7UQEHy`

2. Use this iframe src pattern:
   - `https://open.spotify.com/embed/playlist/{playlist_id}`  
   - Example full iframe:
     ```html
     <iframe
       src="https://open.spotify.com/embed/playlist/33TpZTRBetxMqTWC7UQEHy"
       width="100%"
       height="380"
       frameborder="0"
       allow="encrypted-media"
       loading="lazy"
       title="thecueRoom Weekly Curated Playlist"
     ></iframe>
     ```
   - Put the iframe inside a responsive container and lazy-load it so it doesn't affect initial page paint.

3. Alternative (if you need more control): use Spotify Web Playback SDK for authenticated playback inside the app (requires user auth + more complexity). Use iframe unless you need in-app play control across tracks.

4. Playlist metadata & items
   - To display track list & cover art inline, fetch Spotify track metadata via Spotify Web API (requires client credentials with token).
   - Worker should save metadata (artist name, track title, preview_url, cover_image) into playlist_items table so the UI can show a native track list even if embed is blocked.

Testing checklist (manual)
--------------------------
1. Set env vars and run DB migrations.
2. Start the worker locally (node packages/server/playlistWorker.js) or trigger /api/playlists/curate/run manually.
3. Verify a candidate playlist is created in DB with status='queued' and auto_curated=true.
4. As Admin: open PlaylistEditor -> load candidate playlist -> inspect AI confidence scores per track -> approve & publish -> confirm playlist status='live' & curated_at populated.
5. As User/Artist: open Dashboard -> LatestPlaylistWidget -> confirm Spotify embed loads and plays tracks.
6. Test Artist "Suggest a track": submit suggestion -> confirm item in suggestions table and appears in Admin PlaylistEditor.
7. Test auto-publish fallback: set policy to auto-publish & create a high-confidence draft -> wait configured interval -> confirm publish succeeded.
8. Run unit tests & E2E test that simulates full flow.

Developer notes & caveats
-------------------------
- Spotify: use client credentials flow for metadata; store tokens securely and refresh when expired.
- OpenAI: use concise prompts to score tracks; ensure costs are monitored; batch prompts where possible.
- Worker memory & runtime: run heavy fetches and OpenAI calls in a worker/VM; avoid long-running operations in serverless request handlers.
- Embeds: some users may block iframes via adblockers — always display fallback track list with direct platform links.
- Privacy: do not expose service keys; admin endpoints must be protected.
- Rollback: keep previous playlist versions in playlist_history for quick rollback.

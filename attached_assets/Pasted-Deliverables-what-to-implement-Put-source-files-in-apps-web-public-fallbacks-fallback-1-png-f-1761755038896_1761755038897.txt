New server-side endpoint(s):

GET /api/fallback-thumb/:id

:id = any unique string (use article id, feed url hash, or the path used by client).

Returns an optimized image variant. Query params: ?w=300&format=webp or ?w=600&format=png.

Deterministically pick which fallback (fallback_{1..4}.png) using hash(id) % 4.

Support size presets: small (300), medium (600), large (1200).

Use safe streamed response (no huge buffers).

Response headers: Cache-Control: public, max-age=31536000, immutable for generated files; ETag and Content-Type.

If the worker cannot generate WebP, gracefully return PNG.

On-demand resizing + caching pipeline:

Use sharp (or a JS fallback if native fails).

Implement an async background worker that:

Accepts a job (source fallback image + params), produces optimized file on disk under /.cache/fallbacks/{id}-{w}.{format}.

Limit concurrency by FALLBACK_WORKER_CONCURRENCY env var (default 2).

If cache exists, serve immediately — do not re-generate.

For Replit/test environments where sharp native install fails, implement a JS-only fallback:

Rasterize via an SVG wrapper + @svg2png-js or create resized <canvas> via node-canvas (TEST_MODE).

Clean up old cache files older than FALLBACK_CACHE_TTL hours via scripts/diag/cleanup-fallback-cache.js.

Otherwise return /api/fallback-thumb/:id?w=...&format=webp (choose id derived deterministically from article GUID/URL).

Use a small LRU in-memory cache (TTL ~ 60s) for HEAD result to prevent repeated HEADs on hot articles.

Use AbortController with per-fetch timeout for any external HEAD requests.

Implementation specifics (file list & core code behaviour)

apps/web/public/fallbacks/fallback_1.png ... _4.png (pre-uploaded)

apps/web/app/api/fallback-thumb/[id]/route.ts

Validate params, compute fallbackIndex = hash(id) % 4

desiredWidth = Number(req.query.w) || sizePreset

format = webp|png with Accept negotiation

cachePath = ./.cache/fallbacks/${id}-${desiredWidth}.${format}

if exists -> stream file with res.setHeader and fs.createReadStream

else -> worker.enqueue({ source: public/fallbacks/fallback_${index}.png, width, format, outPath: cachePath }) and await worker result or stream progressive placeholder until done. (Prefer: if worker will take >100ms, return 202 with Location to poll; but simplest: generate quickly in request path but with concurrency limiter)

Worker queue with p-limit; uses sharp pipeline: sharp(source).resize(width).toFormat('webp', { quality: 80 }).toFile(outPath) (stream version)

Small sample deterministic hash (to implement)
// simple stable hash
function hashToIndex(id: string, buckets = 4) {
  let h = 2166136261 >>> 0;
  for (let i = 0; i < id.length; i++) {
    h ^= id.charCodeAt(i);
    h = Math.imul(h, 16777619);
  }
  return Math.abs(h % buckets);
}

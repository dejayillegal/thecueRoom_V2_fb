Task: Fix navigation redirects, eliminate memory leaks, remove scroll lag and browser hangs, and optimize overall client & server performance across the thecueRoom Next.js app. Keep the existing dashboard neon theme, layout and components, but make the app "fast as it can be" on desktop browsers (Chrome / Safari) at typical laptop hardware.

Scope & Goals (must be followed exactly)
1. Fix all navigation links so they always redirect to the correct route (client and server). Ensure links use Next.js `<Link>` or `router.push` correctly and do not cause full reloads.
2. Ensure header/search, sidebar, and per-page navigation do not cause layout shift, reflows, or repeated re-renders.
3. Identify and fix common sources of memory leaks and long-lived event listeners across the client:
   - Remove duplicate `setInterval`/`setTimeout` that aren't cleared on unmount.
   - Remove unbounded `window`/`document` event listeners (resize/scroll/visibility) or ensure proper cleanup.
   - Fix repeated subscriptions to global websocket/SSE connections (make single shared connection).
4. Eliminate scroll lag and stutter caused by heavy paint or JS on scroll:
   - Use `will-change`, `transform`-based animations instead of `top/left` or heavy reflows.
   - Use `position: sticky` instead of JavaScript scroll position for header/sidebar where possible.
   - Virtualize long lists (forum threads, feeds, playlists) with a simple VirtualList component (react-window or manual virtualization) and implement for forum list and news feed.
5. Prevent browser tab hangs:
   - Offload heavy tasks (feed ingestion, image processing, PDF generation) to background workers — for dev simulate with Web Worker fallback or server-side worker. Create a simple web worker stub for client CPU work and wire heavy JSON processing to worker.
   - Debounce expensive inputs (search, filters) with 300–500ms debounce.
6. Improve data fetching & caching:
   - Use `stale-while-revalidate` pattern (SWR) for feeds/pages. Configure sensible cache TTL and background refresh.
   - Avoid waterfall fetches on page load — fetch in parallel.
   - Add a simple LRU in-memory cache on the server for frequent external fetches (RSS) with TTL.
7. Make navigation accessible & keyboard friendly: focus management, return focus to meaningful elements on route change.
8. Add automated tests that assert no open intervals/listeners remain after unmount using unit tests and a memory-leak detector test (simple count of active timers/listeners).
9. Add performance benchmarks and developer scripts:

Implementation details & exact fixes the agent must apply
1. Navigation & redirects
   - Centralize all routing through `navigateTo(route, { replace?: boolean, scroll?: boolean })` in `lib/navigation.ts`. All existing `Link` or `router.push` calls must be replaced to call this helper OR keep `<Link>` for static navigation. If a Link is used for client-only navigation, ensure `prefetch={false}` where prefetch harms performance.
   - Convert any `a` tags that cause full page reloads to Next `<Link>` when routing internally.
   - Ensure `router.replace` is used for redirect-like behaviour (login redirect, logout) to avoid stacking history.

2. Memory leaks & event listeners
   - Replace any `useEffect` adding `window.addEventListener('scroll',...)` with `useEventListener` hook (auto-cleanup).
   - Add `use-safe-interval` for intervals and replace raw `setInterval` usage.
   - Make sure `useEffect` that subscribes to data streams returns cleanup function that unsubscribes and cancels pending fetches (AbortController).
   - Search repo for patterns: `setInterval(`, `addEventListener(`, `new WebSocket(` and patch with safe hook or shared singleton. The agent must modify all occurrences found.

3. Virtualization & list rendering
   - Implement `VirtualList` using a simple windowing algorithm (no external deps) with props: `itemHeight`, `height`, `items` and `renderItem`.
   - Replace forum and news feed lists with `VirtualList`. Ensure keyboard focus and accessibility are preserved.
   - Add test asserting that DOM child count << items.length after virtualization.

4. Worker offload
   - Add a tiny web worker (jsonWorker.ts) that can be spawned via `new Worker(new URL('./jsonWorker.ts', import.meta.url))` and used to process heavy JSON parsing or image metadata extraction.
   - Update feed ingestion client-side logic to parse large RSS items in worker and return smaller object to UI.
   - For server-side heavy tasks, ensure a Node worker (scripts/worker-dev-setup.sh) can be started to process CPU jobs. Update server code to POST heavy tasks to the worker endpoint instead of doing them inline.

5. Caching, parallel fetch & circuit breaker
   - Implement `cache.get(key)` with TTL; feed refresh endpoint checks cache before fetching.
   - Parallelize initial page load data fetches via `Promise.allSettled`.
   - Add `circuit-breaker` simple counter: if a feed fails 3 times recently, mark as disabled for 1h to avoid repeated hit and slowdowns.

6. Debounce inputs & avoid re-renders
   - Debounce search input with `useDebouncedValue` hook (300ms), avoid re-rendering large lists until debounce completes.
   - Memoize heavy components (Avatar, Card, ListItem) with React.memo and appropriate prop equality checks.

7. Shared socket
   - Implement `useSharedSocket` hook that returns a singleton socket instance. Replace direct socket creation in pages/components to prevent multiple socket connections.

8. Tests & CI
   - Add vitest tests described above. The memory leak test should mount a component that uses intervals, then unmount and assert no active timers via a small helper that checks `window.__tcr_active_timers` (instrument setInterval wrapper in use-safe-interval to increment/decrement a global counter in test mode).
   - Add CI step `pnpm check:leaks` to fail if leaks detected.
